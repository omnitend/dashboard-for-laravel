# DXField

The single-field renderer that powers `DXForm` and
`DXTable`'s edit modal. It renders one `FieldDefinition` of any type — wired to
a `useForm` instance for value binding, validation state, and error display —
and exposes `#value`, `#span`, `#info`, `#info-popover`, `#hint` and
`#password-actions` slots for per-field customisation.

You will usually reach for `DXForm`, but `DXField` is
available directly for one-off fields or custom layouts. It binds via a dot
path (`keyPath`), so it also works for nested values such as repeater rows
(`lines.0.price`).

## Display-only and password field options

Two `FieldDefinition` options change how a control is rendered rather than what
it holds (the full schema lives on the
[DXForm](/components/extended/DXForm#field-definitions) page):

<PropsTable client:load props={[
  { name: 'plaintext', type: 'boolean | (model) => boolean', required: 'No', default: 'false', description: 'Display the value as static text instead of a control — no border, no input box (Bootstrap’s .form-control-plaintext). Implies read-only for every field type: anything backed by a real input (the text family, textarea, currency, percentage, autocomplete) renders as static text, while control types with no native readonly state (select/radio/checkbox/switch/file) are disabled instead.' },
  { name: 'revealable', type: 'boolean', required: 'No', default: 'true', description: 'Only for type: "password". Shows the reveal (eye) toggle that switches the input between masked and plain text. Set false for a bare password input.' },
]} />

`readonly` is unchanged: it still renders a bordered, non-editable control, which
reads as "you could edit this, but can't". Use `plaintext` for values a
profile/settings page shows but never lets you edit.

`revealable` is on by default, so every password field gets the eye toggle
unless you opt out.

`inputProps` remains an escape hatch that wins over the field's own bindings —
`inputProps: { readonly: true }` works as before — but it cannot override the
guarantees these two options make. A `plaintext` field cannot be made editable
through it, and the reveal toggle owns the password input's `type`, so an
`inputProps` `type` cannot unmask a field whose toggle still reads "Show
password".

A revealed password is also re-masked whenever the field is reseeded with a
different record, which is what `DXTable`'s edit modal does between rows.

### Password actions

The `password-actions` slot places your own controls beside a password input,
inside the same input group, after the eye. Its props can write the value
(`update`) and drive the eye's state (`revealed`, `setRevealed`), so a
"Generate password" button can fill the field and show what it generated
while the input and the eye stay dfl's own:

```vue
<DXField :field="{ key: 'password', type: 'password', label: 'Password' }" :form="form">
  <template #password-actions="{ update, setRevealed, disabled }">
    <DButton variant="outline-secondary" :disabled="disabled"
      @click="update(generatePassword()); setRevealed(true)">
      Generate
    </DButton>
  </template>
</DXField>
```

- The eye keeps working by itself, and keeps its `aria-label`/`aria-pressed`;
  `setRevealed` changes the same state, so the two always agree.
- `disabled` is true when the field is disabled or read-only.
- The content shares the input's row, so keep it short: on a phone a long
  button label squeezes the input until the revealed password cannot be read.
  An icon-only `DButton` needs an `aria-label`.
- The slot does not render on a `plaintext` field (there is no input).
- On a `revealable: false` field the slot still renders (the input gets the
  group for it), but there is no eye and `setRevealed` does nothing: the
  field never unmasks.
- A field without the slot renders exactly as before.
- Slot props are typed as `PasswordActionsSlotProps`. In `DXForm` the slot is
  `password-actions(<key>)`; in `DXTable`'s edit/create modal it is
  `edit-password-actions(<key>)`.

```typescript
const fields = [
  // Static text, no input box.
  { key: 'email', label: 'Email', type: 'text', plaintext: true },

  // Editable until the record is verified, then display-only.
  { key: 'vat_number', label: 'VAT number', type: 'text', plaintext: (model) => model.verified },

  // A bare password input, without the reveal toggle.
  { key: 'password', label: 'Password', type: 'password', revealable: false },
];
```
